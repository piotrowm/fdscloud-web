How to Define a Design Fire Scenario for FDS

A practical route from a fire-safety question to a defensible FDS scenario: fire location, HRR development, ventilation state, geometry and acceptance criteria.

Start with the engineering question

An FDS model should not begin with a mesh. It should begin with the decision the analysis is intended to support. Examples include smoke-control performance, tenability on an evacuation route, smoke spread between zones, detector response or sensitivity to fire location.

1. Identify credible fire locations

Fire position can materially change smoke movement and system response. Locations near exhaust points, supply openings, doors, obstructions or high-risk fuel packages may therefore need separate scenarios. A single centrally located fire should not automatically be treated as representative.

2. Define HRR(t)

The heat-release-rate curve is one of the key scenario inputs. Document the basis for the growth phase, maximum HRR, any steady period and decay if modelled. The chosen curve should be linked to the assumed fuel package and the purpose of the analysis rather than selected only because it is convenient to simulate.

3. Define the ventilation state

Doors, leakage, natural openings, mechanical supply and extract can dominate smoke movement. Record which systems are operating, when they activate and which openings are assumed open or closed. Alternative ventilation states may form separate scenarios.

4. Define outputs before running

Decide in advance what will be evaluated: visibility, temperature, gas concentration, smoke-layer height, velocity, pressure or detector activation. Place devices and slices to answer those questions, not merely to produce attractive Smokeview images.

Engineering principle: a design-fire scenario is a documented set of assumptions. FDS calculates the consequences of those assumptions; it does not decide whether the scenario itself is appropriate.

5. Build a scenario matrix

A useful matrix combines fire location, fire development, ventilation/system state and relevant boundary conditions. Screening can then identify which combinations need detailed simulation and which assumptions require sensitivity analysis.
